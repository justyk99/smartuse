# Changelog

## 0.4.0 — in progress (2026-10-22)
- **Heartbeat.** `hooks/heartbeat.py` runs on SessionStart · UserPromptSubmit · PreToolUse/PostToolUse (every tool) · SubagentStart/SubagentStop · Notification (idle, permission) · Stop · SessionEnd and writes `~/.claude/smartuse/projects/<repo>/status.json` (~45 ms per event, 0 model tokens). `/smartuse:status` renders one line by fixed priority — `NEEDS YOU: …` · `session ended` · `waiting on you: permission prompt` · `working · waiting on agent: <type> <elapsed>` · `working · <tool> running <elapsed>` · `waiting on you · <since>` · `working · last <tool> <ago> · N calls`, with `stalled?` after 5 minutes without an event (`SMARTUSE_STALL_MIN`) — plus `step 3/6 build·opus "…"` and `loop block 2/6` from routing.json. `/smartuse:status install` prints the `statusLine` snippet (`--statusline` merges model, context % and cost); the plugin ships a `subagentStatusLine` naming the plan step on each agent row (runtime loading of plugin settings unverified). Stop only counts as "waiting on you" when the until-done gate will not refuse it. 54-case test; one live headless session verified every event lands. Design: `docs/notes/heartbeat-design.md`.
- `bench/ab.sh` + `ab-report.py`: the routed-vs-not A/B runner — one kickoff per ask, then `run-plan --until-done` per dial (off / safe / aggressive) on fresh copies, receipts read from the hook archives, a comparison table (steps, npm test, agent output by model, cost, minutes, turns, deltas vs off, medians). `fake-claude.sh` dry run in CI; the real run spends ≈ $5–6 per ask per dial.
- Receipts: `by_model` on every agent receipt, `agent_by_model` on the plan step, the summary line shows the agent-output share by model (`haiku 45% · fable 40% · sonnet 13%`) instead of an always-100 % "delegated" figure; `--receipts [task|all] --json`. ledger-test 17 cases.
- run-plan: an open question that the kickoff already answers with an `assumed:` default is not a blocker — proceed, record it in `decisions.md`, list it under **Confirm**; only a question with no default or a rule gate blocks. Found by the first real A/B run (two of three dials stopped before any step on an assumed value; `bench/results-example/2026-10-22-ab-run1/`).
- Windows: `hooks/py.sh` picks `python3` / `python` / `py -3` and skips the Microsoft Store stub (on a stock Windows install no hook had ever run); hooks read `HOME` before `expanduser` so Git Bash and the tests' temp HOME are honoured. Found by the first run on the author's laptop. Round 2 from the laptop's re-test: paths inside the event JSON are converted when Git Bash cannot (`native_path`), the renderers print UTF-8, the tests tolerate slow process start; `until-done` never trusts a pin file on Windows (every file reports owner 0 there). bash-guard 48 cases, heartbeat 55, until-done 24. All five suites verified green on the author's Windows laptop (Git Bash, Python 3.13) on 2026-10-22.
- Design notes: `docs/notes/receipts-design.md`, `docs/notes/heartbeat-design.md`.

## 0.3.0 — 2026-10-22, "a receipt per plan step"
- **One receipt per plan step.** `run-plan` marks the unit it is about to run as `running`; the `SubagentStop` hook attaches that agent's real API calls and tokens (`agent_calls`, `agent_input`, `agent_output`, `agent_models`, `agents`) to that unit in `routing.json` — never estimated, never guessed (two running units → the receipt line stays unattached). Build and verify agents on the same step accumulate. The unit also records the user's retier as `override: {from, to, by}`, the one escalation, and the fresh-agent verdict `verify: no gaps | gaps fixed | gaps open`.
- **`/smartuse:receipts [task|all]`** — new skill, 0 model tokens to compute: one row per plan step (`# · step · tier · model · override · outcome · esc · verify · calls · in · out · check`) plus the delegated share ("delegated out 4.0k, 100% of agent output on sonnet"). Closed runs are archived by the Stop hook under `~/.claude/smartuse/projects/<repo>/runs/<started_at>_<task>.json`, so a task's receipts outlive the next run.
- `run-plan --until-done`: the lazy-CEO loop. A Stop hook (`until-done.py`) refuses to end the turn while units or the repo's `check` command are unfinished; the model stops only for a real human question (`needs_human`), a double failure, a rule gate, or after 6 blocks. 23-case test.
- Adapter field `check:`; `file-guard` hook (PreToolUse on Write/Edit) keeps the adapter and the pin file human-only.
- First end-to-end run on the bench repo (2026-10-15): one line → kickoff (14/14) → loop built the endpoint + 4 tests (11/11), verified end to end, stopped with a precise human question (pre-existing lint gap) instead of guessing; $1.30, 5.6 min, 19 turns. Artefacts in `bench/results-example/2026-10-15-csv-export/`. That run exposed the gap this release closes: the hook's per-agent token lines were not joined to the plan steps, so the receipts table carried self-reported numbers.
- Security hardening of the gate (4 review rounds): check command only from the human-written adapter, fixed shapes, root-owned pin file for bash scripts, file-guard on the two human-only files, TTY-faker denial.
- ledger: `started_at` kept in the record; `--recompute` uses it (or a 15-minute window when missing / future); one receipt per agent even with two SubagentStop hooks; GitHub token files (`gh/hosts.yml`, `.git-credentials`, `.netrc`) count as credential files in bash-guard.
- Repo: CI runs all four hook tests (bash-guard 44 cases · file-guard · ledger + receipts · until-done) and strict validation of plugin and marketplace; `scripts/term-scan.py` (generic private-term patterns + an optional gitignored `.smartuse-terms.local`, never printed) runs in CI as a warning and by hand before a public push; internal names in design notes and test fixtures replaced with neutral ones.
- Verified end to end on 0.3.0 (2026-10-21, headless, Claude Code 2.1.306): the same bench ask → kickoff 14/14 ($1.57) → `run-plan --until-done` 6 steps, 6/6 tests, three reviews "no gaps", step 6 blocked by rule; the hook attached every agent's tokens to its step (agent out 10.0k: fable 40 % · haiku 45 % · sonnet 13 %). $3.72, 6.4 min, 22 turns. `bench/results-example/2026-10-21-csv-export/`. Demo gif rendered from that run's captured output (`scripts/render-demo.py`).
- Tests: ledger-test 13 cases (7 new for the receipt per step, the archive and `--receipts`); bash-guard 44; until-done 23; file-guard 4. Hook tests and strict validate green on Claude Code 2.1.306.

## 0.2.0 — 2026-10-15, first public release
- Renamed from `yk-kit` to `smartuse` before the first push (no installs existed under the old name).
- Repository scaffolding: CI (hook + ledger tests, strict manifest validation), issue and PR templates, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, `docs/research` and `docs/notes`.
- living-docs is now model-invocable (`disable-model-invocation` removed) so the commit procedure can call it without the user typing anything; run-plan stays manual-only on purpose (it spends plan usage).
- Verified on real work (2026-10-15, Claude Code 2.1.300, Max plan): two `make-prompt quick` kickoffs on live repos — 0.9 min / 3.9k output tokens / 205k cache reads (a phase that turned out to be already built) and 1.8 min / 3.7k out / 195k cache reads (a parked design decision, 12/13 self-check); one `run-plan --units 1` on the second kickoff: tiered the unit mechanical → haiku agent (7 calls, 24k out), honestly marked it `blocked` by a read-only DB rule instead of working around it, receipt + visibility line written; the Stop hook wrote the ledger lines from the headless sessions by itself.
- Token counting: records that share one message id are partial views of one API call — keep the max of each counter per id (the first-record rule undercounted a 24k-token agent as 23). `ledger.py --recompute` rebuilds old lines.
- Plugin evals (2026-10-15, Claude Code 2.1.300, `--runs 1`): **4 of 4 cases pass with the kit (score 1.00 each); without the kit 0.00 / 0.00 / 0.50 / 0.00; mean gain +0.88; $1.27 list price per full run.** First runs found two real faults (a kickoff that was lost when the sandbox refused the save; living-docs not naming what was missing) — both fixed. `evals/results/2026-10-15-final/aggregate-result.json`.
- Plugin evals: need an OS sandbox for shell tools (`bubblewrap` + `socat` on Linux); graders must use JavaScript-safe regex (no `(?i)`), YAML single quotes for backslashes, and `allowed_tools` per case.
- ledger: Stop / SubagentStop hook writes `~/.claude/smartuse/ledger.jsonl` (per-task tokens by model, minutes, self-check) and per-agent receipts; `/smartuse:ledger` report; shared message ids counted once; self-contained test.
- run-plan: tier plan (judgment / build / mechanical / verify) with a dry-run table, foreground agents with a model per tier, one escalation, fresh-agent verification, receipts per unit, dial off / safe / aggressive.
- evals: 4 cases (kickoff-quick, reply-style-catalogue, bash-guard-sudo, living-docs-no-root) for `claude plugin eval`.
