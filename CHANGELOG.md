## 0.7.3 — 2026-11-26, "the ledger line is kept"
Two Stop hooks at once no longer lose a run's ledger line, doctor names a paid counter left in a folder it no longer uses, and the publish scan reads history on newlines only. No new rule, gate, adapter key or option; no line of `bash-guard.py` or `fit_key` changed. Plan: `docs/notes/0.7.3-plan.md`.
- **The ledger line is kept** (F1). With two Stop hooks at once (a user-level copy and the plugin's) on Windows, one hook's read of the claimed `pending.<pid>.claimed` could fail with a sharing violation while the other still held the file for its rename; the hook then deleted it and no line was written (3 to 4 rounds in 1,000, 0.7.2 E1). The read now retries a `PermissionError` 5 times, 20 ms apart (the `write_json` shape), returns when the other hook has taken the file, and deletes the claimed file only when its content is bad (deep nesting included); one still unreadable after five tries is left, and the claim replaces a file a reused process id left behind. 1,000 rounds of two real Stop events on the author's laptop: one line each, five of them through the retry.
- **Doctor names a counter left behind** (F2). With Windows long paths off, a project whose full-key state folder is longer than 232 characters moves to the short key, and a `paid-runs.json` in the full-key folder stays there. The paid check then refuses every paid run ("two state folders hold a counter") while doctor said `state folder: writable`. Doctor now prints its own `state folder: FAIL` line naming both folders, the counter folder's length and both ways out (long paths back on, or delete that folder). Measured (E1) with long paths off: a full-key folder of 240 or 244 characters holding the counter is refused; at 245, 250 and 270 the counter's own path passes 259, the paid check does not see it and the count starts again in the short folder. The layout starts at 233 characters (below that the full-key folder is kept). That is in `SECURITY.md`, and its fix is on the ROADMAP.
- **The scan reads history on newlines only** (F3). `scripts/term-scan.py` split git's history output at a bare carriage return too, so text after one could pass for a `commit`, `diff --git`, `Binary files` or `ident` line and be skipped (history only). History is now framed on newlines, git's own lines are known on whole lines, and a content line, or an author or committer name, is still scanned in its carriage-return pieces. The old and the new script give the same hits over this repo's whole history (718 at `e7328d5`, 0 private); the release scan finds 0 private (the new test cases add generic hits).
- **The rule-name check fails, never skips** (F4). `heartbeat-test.sh` skipped its `KNOWN_RULES` comparison when `bash-guard.py` had no `RULE_NAMES`, a branch from before 0.6.1; a lost `RULE_NAMES` now fails it.
- E2: the recall count 210 quoted for 0.6.0 and 0.6.1 was counted in a Windows shell that could make links (12 link cases run in place of 5 skip lines: 203 − 5 + 12).
- **Counts and versions.** The badge said 4376 hook + 36 bench; it now says 4395 hook + 36 bench, PASS only, by the same rule. Plugin and marketplace 0.7.3. `RULE_NAMES`, `GATE_NAMES`, the floor and `hooks.json` are unchanged. `README.md`, `SECURITY.md` and `docs/ROADMAP.md` follow.

Against 0.7.2: ledger 46 → 53, heartbeat 213 → 219, paid 1397 → 1403.

## 0.7.2 — 2026-11-25, "the scan reads every line"
The publish scan reads each line whole, a made state folder keeps the paid count, a folder too long for paid runs is named, and a test that did not run says SKIP. No new rule, gate, adapter key or option. Plan: `docs/notes/0.7.2-plan.md`.
- **The scan reads every line whole** (F1). `scripts/term-scan.py` kept only the first pattern that matched a line, and the generic patterns came first, so a private term on a line with another hit was not counted and showed in its excerpt. Now every pattern is tried on every line, private first, and every private match is starred in the excerpt, the generic hits' excerpts included. Commit messages and file paths are scanned too. A line that is not valid UTF-8 is read a second time as cp1252, a line with NUL bytes (UTF-16 text) also without them, and a private match in any reading is starred in every excerpt; the summary counts such lines in text files (images are not counted). History also reads files git calls binary, author and committer names and e-mails are checked for private terms, and `--max-hits` caps only the generic rows, so a private hit is never dropped (the summary says when the cap was reached). Diff header lines are skipped only inside a diff header. It may report more generic hits than before.
- **A made folder keeps the paid count** (F2). A project whose short-key folder holds `paid-runs.json` stays on the short key when a full-key folder appears, in all six copies of `fit_key`, so a made folder no longer restarts the count. The short key is chosen only when the short folder holds a counter and the full-key folder does not. A counter in both folders is refused: the paid check denies ("could not verify the go (two state folders hold a counter); run /smartuse:doctor", checked again under the counter lock) and doctor prints a `state folder: FAIL` line naming both folders. Windows only. Limits are in `SECURITY.md`.
- **A kept folder too long for paid runs is named** (F3). In a kept state folder whose path leaves too little room for the counter's files (Windows, long paths off), a paid call was refused with a pointer to the adapter, and doctor said `state folder: writable`. The refusal now names the state folder and `/smartuse:doctor`, and doctor prints a `state folder: FAIL` line with the length and the ways out. Doctor's probe is 49 characters (the longest claim marker, the second script's), and the FAIL line is printed only when the folder path is really over 209 characters (otherwise it says the folder cannot be written); from 210 to 218 characters it says only some paid runs (two scripts in one command) cannot be counted. Still a deny at both levels.
- **A test that did not run says SKIP** (F4). Cases that cannot run on a machine (symlinks, Windows-only checks) printed `PASS`, so they counted in every suite's number. They now print `SKIP <label>`, are not counted, and `all.sh` shows ` · M SKIP` on the suite's line. Counts are now PASS only, so the badge's number counts PASS only: a lower suite number than 0.7.1's is not a lost test. The laptop's SKIP count depends on two switches: Windows Developer Mode (symlinks without admin) and running as admin. The `fit_key` import check in `wait-gate-test.sh` now reads every import in the module, so a top-level `import winreg` fails it.

Two Stop hooks at once on Windows: hook A renames `pending.json`, but hook B still has the file open for its own rename, so A's read fails (a sharing violation, `PermissionError`); A then deletes the claimed file and B's rename fails, and no line is written. 3 rounds in 1,000 on the author's laptop; a held delete handle reproduces it every time. Plugin and marketplace 0.7.2. `RULE_NAMES`, `GATE_NAMES`, the floor and `hooks.json` are unchanged. `README.md`, `CONTRIBUTING.md`, `SECURITY.md` and `docs/ROADMAP.md` follow.

- **Changed defaults.**

## 0.6.1 — 2026-11-11, "lighter, faster, switchable"

  - A read of `~/.claude.json` is denied only in Strict (the `claude-json` rule, off in light; light behaves as 0.6.0 did).

## 0.6.0 — 2026-11-10, "the summary is not a source"
A long session gets compacted: Claude keeps a model-written summary and loses the exact words, and can then work from the summary while the job's real files sit unread on disk. Claude Code already reloads CLAUDE.md, memory and a few recent files after a compaction; it does not know which files are this job's sources, and nothing refuses a send made from the summary. recall adds the refusal and the pointer, not a store (design and contract: `docs/notes/recall-design.md`).
- **The fresh-source gate** (in bash-guard). The adapter names the job's `sources:` and the commands (`publish:`) or upload tools (`publish_tools:`) that send its output. Such a call is denied until every source has a Read in this session after the last compaction; the reason names the unopened files. Files Claude Code re-attaches after a compaction are not Reads and do not count (checked on a real transcript). A send is found behind `timeout`, `env`, `nohup`, `sudo`, `winpty` and other wrappers, inside `$(…)` and backticks, in PowerShell (the hook matcher is `Bash|PowerShell`), and a `-c` / `eval` string handed to another shell counts as a send while the sources are unopened (see Security review), with the script given by any path (`python -u C:/repo/send.py` matches `publish: python send.py`; `python3` and `py` are `python`). Tools: one PreToolUse entry for `mcp__` tools whose name holds upload, send, publish, post, share or submit. Fail open on detection errors, fail closed once a send matched; one 4 s deadline. Source values must be plain local paths, and links are refused, never followed.
- **recall at the squeeze** (`hooks/recall.py`). PreCompact tells the summarizer to keep the source paths and the owner's last 8 prompts verbatim and to mark anything not re-verified as "from summary" (Claude Code uses that output as summary instructions). Right after the squeeze, Claude is told "The summary is not a source." and which files to reopen. The status line counts squeezes: `· squeezed 2× (last 14:02)`. Everything printed is scrubbed (tokens, e-mail addresses, long digit runs; file names keep their digits) and capped at 9,000 characters.
- **The handoff pointer.** `handoff: docs/STATUS.md` prints that note's first 15 lines and its age on every new, cleared or resumed session, with `stale: the handoff is N days older than the last commit` when it is. A resumed session with a compaction in it hears that the compacted part is a summary. The file must be a plain file inside the repo.
- **Reviews.** A fresh review and an automated one found, among others: an absolute script path that skipped the gate, brackets in the repo path that broke every source glob, a scrub that broke file names, links and automount paths that could reach a share, and matcher gaps; all fixed with tests that fail on the code before them. Limits that remain are listed in the README and the contract.
- **Security review** (of the code above, before release; plan `docs/notes/recall-security-fix-plan.md`). It found that the gate's two promises, "gated on every path" and "fails closed once a send matched", each had a hole. The batch went through ten review rounds; one fix round was reverted after its review found regressions. Early rounds found new crafted-command classes, several caused by the previous fix, so it ended with a different rule: a command the gate cannot read counts as a send while the sources are unopened. Fixed, each with tests that fail on the code before them:
  - **The closing rule: a command the gate cannot read counts as a send while the sources are unopened.** Classes: a very long command (over 32 KB), heredocs past the scan cap, three or more command substitutions, a `-c` / `eval` / `iex` / `cmd /c` / `-Command` string handed to another shell, and in PowerShell typographic quotes or dashes, escaped quotes, a block comment (`<#`), and `Start-Process` (or `start` / `saps`) as a standalone word anywhere in the command (its arguments are not read). With `publish:` listed and a source unopened (right after a compaction, or before the sources are first opened), a PowerShell command that holds the word `Start-Process`, `saps` or `start` anywhere is denied once until the sources are re-read, including `npm start`, a `$start` variable or the word inside a quoted string. A backtick escape inside that word is not caught yet (0.6.1). The reason names the class and says to open the sources or simplify. Once the sources are opened, such a command is read as before. It counts only when the adapter lists `publish:`. The cost is one turn for an unusual but harmless command right after a compaction. For a command over 4,096 characters the source check runs before the older rules.
  - **Another shell.** On Windows the PowerShell tool is on by default for claude.ai accounts, and it never reached bash-guard. The hook now runs for `Bash|PowerShell`; the older rules and the gate read the PowerShell text. The match is coarse: a publish word anywhere in a statement counts, so an unquoted `Write-Host git push` is an over-deny (one turn); a form it cannot read (typographic quotes or dashes, an escaped quote, a block comment, a `Start-Process` word) counts as a send while the sources are unopened. An adversarial PowerShell tokenisation pass is listed for 0.6.1. An encoded PowerShell command that does not decode is denied with its own reason; one that does is a string handed to another shell (counted as a send while the sources are unopened). `CLAUDE_CODE_USE_POWERSHELL_TOOL=0` turns the tool off. From Claude Code 2.1.314 (confirmed on 2.1.321), Monitor commands reach the same check.
  - **A slow command.** A crafted command could keep the heredoc scan busy past the hook's 10 s timeout, and a hook that times out lets the call through. The deadline now starts when the hook starts, and the heredoc scan has a bound on heredoc openers and delimiter length; past it the bodies are read as code (an over-deny) or, as a whole, as a command the gate cannot read. A 48 KB command that took 4.84 s + 5.39 s in the two scans is now denied in 0.31 s (median wall of 5 runs, interpreter start included; the maintainer's laptop, 2026-11-10).
  - **More spellings of a send** are read: wrappers and package runners, here-strings, `echo` or `printf` piped into a shell, git aliases, command names in any case, more shell names, a script name with a trailing dot or space.
  - **A failed Read is not an opened source.** A Read whose result is an error (a missing file, a denied Read) no longer counts; a Read whose result never arrived still does.
  - **A `:` inside a path part, or a part of only dots**, in a `sources:` or `handoff:` value is refused by its text, before any file call.
  - **recall's e-mail scrub** is linear in the length of the text, and a pasted blob is cut before it is scrubbed.
  - Not fixed, and said so: a command built at run time is not seen; the frozen older rules are slow on a very long, dense command (when the sources are opened or there is no adapter, such a command can outlast the hook timeout); a Python start slower than about 6 s is outside every deadline; some other ways of handing a command to another shell or interpreter are not yet recognised as such (other spellings of the same launchers, text fed on standard input, process substitution, shell functions and traps), and are listed for 0.6.1; the PowerShell side does not yet have the older rules for write verbs, download-then-run and script-file bodies. The limits are listed in the README and the contract; the rest is on the roadmap.
- **The credential-file rule no longer covers `~/.claude.json`** (owner decision). `Read(~/.claude.json)` in the security profile keeps that protection for those who want it; the other credential files stay covered.
- **term-scan** exits 2 when the private term list is missing (a scan without it is not clean); `--no-private` for CI. CI's Python 3.9 job runs on ubuntu-24.04 (ubuntu-latest has no 3.9).

## 0.5.1 — 2026-10-25, "the launcher remembers a name, not a path"
- **The launcher's remembered interpreter is a name now.** In 0.5.0 `hooks/py.sh` ran the absolute path stored in `~/.claude/smartuse/interpreter`, an ordinary user-state file that neither guard listed: a writable state file chose the program every hook ran, in every repo (found by the push security review, 2026-10-25; plan `docs/notes/py-cache-fix-plan.md`). The file may now hold only `python3`, `python` or `py -3`; `py.sh` looks that word up on PATH, exactly as its probe would, and runs it — builtins only, so still one Python start per event. Anything else in the file (a path, another word), a name PATH no longer has or has only as a file that cannot run, or an alias under `WindowsApps` (any case) is ignored and probed again. The file is read up to 16 characters and written only into a regular file or a new one (never through a symlink, never a FIFO). A 0.5.0 cache (a path) is replaced by a name on the first event: nothing to delete by hand. Users whose only Python is the Microsoft Store one or the Python install manager (3.14+, python.org's default; both put their commands under `WindowsApps`) keep 0.4.0 speed, two starts per event, because an alias is never trusted.
- **The file is human-only.** file-guard (Write / Edit / MultiEdit / NotebookEdit) and bash-guard's human-only rule (`>`, `tee`, `sed -i`, `cp`, `mv`, `python -c`, `py.sh`) cover `~/.claude/smartuse/interpreter`, including the spellings Windows maps to the same file (a trailing dot or space of any part, `::$DATA`); file-guard also matches the path the OS resolves (links, junctions, short 8.3 names of what exists; for at most 3 s, failing closed when it gives up) and denies a path under smartuse with a part of only dots and spaces (fail closed), with the reason "…or which Python runs the hooks"; deleting it stays allowed (it only costs one probe). The rule's known limits (ROADMAP) are unchanged; with a name-only cache, a write that gets past them can only pick among `python3`, `python` and `py -3` as PATH resolves them — it can no longer name a program.
- **bash-guard's destructive-SQL rule is linear.** It rescanned the rest of the command from every position, so its time grew with the square of the command's length: 16 KB of ordinary text took 12 s on the author's laptop. It is anchored now, with the same matches (rules are searched with `re.S`), and that command takes under a second.

- bash-guard: a heredoc is checked as code only when a shell, `source` / `.` or `eval` on its opener line reads stdin as commands (`bash <<EOF`, `-s` / `-c`, no script, `bash /dev/stdin`, `cat <<EOF | sh`, a pipe continued after the body); a heredoc fed to `bash script.sh` is that script's input.
