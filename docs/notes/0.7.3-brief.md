## Carry-over rules
- One heavy job at a time on the laptop (tighter than 0.7.2's two); suites never side by side; never `all.sh` there. Claude Code stops a background suite when memory runs low: report it, restart only on the maintainer's word.
- Builder briefs: every "as today" claim gets a file:line the builder has read; a bug gets its red case first; name every import allowlist (four suites have one: wait-gate, recall, paid-guard, fresh-gate).
- `fit_key` is one text in six hooks (heartbeat, bash-guard, ledger, recall, until-done, wait-gate); the wait-gate suite checks the six are equal. A change to one is a change to all six.
- A limit measured on one machine holds only for its switches (D8): name the switch in the rule.
- A rule that trusts "the hook alone writes file X" fails: a folder copy, link or junction can plant X without naming it (0.7.2 D9). Fail closed when two sources disagree.
- Concurrent writers to one log file lose lines on Windows: one log file per process in any experiment.
- Tests use a temp `HOME`. The private terms file and `.claude/*.local.md` are never read or printed; `.agents/` and `.codex/` are never touched. Builders stage files by name.
