## Carry-over rules
- One heavy job at a time on the laptop, at low priority (the maintainer may be gaming); suites never side by side; never `all.sh` there. The way to lower the priority is not written in the repo: the orchestrator names it in each builder brief. Claude Code stops a background suite when memory runs low: report it, restart only on the maintainer's word.
- Builder briefs: every "as today" claim gets a file:line the builder has read; a bug gets its red case first; name every import allowlist (four suites have one: wait-gate, recall, paid-guard, fresh-gate). No feature of 0.7.5 adds an import.
- Every Python start of the plugin goes through `py.sh`, and the start flags live there and nowhere else. `hooks.json`, `settings.json` and the skills' `!` lines are not edited.
- The loader line `LDR` in `py.sh` stays byte for byte. `-P` is never passed (3.9 and 3.10 do not know it).
- `export PYTHONUTF8=1` stays and nothing is unset: a hook's child process gets the environment it gets today.
- The remembered-name file (`~/.claude/smartuse/interpreter`) picks a probe step to skip. Never a command, never the start mode: the second try is never written to it. Its name and both guards' patterns for it do not move.
- A flag reaches an interpreter only if that interpreter passed the probe with the flag in this run, or the file holds the marked word.
- From 0.7.5 a `PYTHON*` variable set in front of the launcher does nothing (only `PYTHONDONTWRITEBYTECODE` is carried, as `-B`). A test that needs one starts the interpreter directly, or it cannot fail.
- A hook file imports the standard library only: the launcher starts Python without the `site` module. `heartbeat-test.sh` holds the allowlist for all eight files.
- Plants (a `json.py`, a `.pth` line, `sitecustomize.py`) go in temp folders and a temp venv only. Never the real home, the real hooks folder, the real user site or an interpreter's site folder. On Windows a temp `HOME` does not move Python's user site: use `PYTHONUSERBASE`.
- An event with a Windows path in it is piped from a file. An empty answer counts only after a known-deny event went through the same pipe.
- A result names its switches (the OS build, the Git Bash version, each interpreter's version and origin, venv or not). What was not measured is written "assumed".
- `py.sh` stays bash 3.2 safe; only CI's macOS job proves it.
- `fit_key` is one text in six hooks, `long_form` and `counter_in` one text in two; none moves in 0.7.5.
- New code in the launcher gets a security review round before T3 (R1). Release text states classes, never the method of a gap that stays open.
- Tests use a temp `HOME`. The private terms file and `.claude/*.local.md` are never read or printed; `.agents/` and `.codex/` are never touched. Builders stage files by name.
- The release needs T3 (both validates, the interactive scenarios, a fresh review and a security review), the bare publish scan showing `(0 private)`, and CI green on the pushed work branch before main moves. Version 0.7.5 goes in both manifests, the CHANGELOG, the badge and the docs in F5, the last feature.
