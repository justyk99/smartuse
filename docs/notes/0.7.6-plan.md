## 2b. What a skill's grant is, and what narrowing changes
Claude Code's skills page: `allowed-tools` "grants permission for the listed tools during the turn that invokes the skill … It does not restrict which tools are available: every tool remains callable, and your permission settings still govern tools that are not listed."

| What the grant decides | 0.7.5 | 0.7.6 |
|---|---|---|
| The skill's own `!` lines (they run as the skill loads; one that is not allowed aborts the skill; no PreToolUse hook sees them) | allowed by `Bash(bash *)` | allowed by a rule that names the launcher, the script and the option |
| A launcher command the model types in that turn (a receipt, a plan step) | runs without a prompt | the same, for the commands in F1's table |
| Any other command that starts `bash ` in that turn | runs without a prompt (`bash-guard` still reads it) | back to the user's own settings: a prompt in default mode, a refusal headless without a permission flag |
| `python3 <anything>` in a reply-style turn | runs without a prompt | back to the user's own settings |
| A command the user allowed in their own settings, bypass mode, auto mode | not the skill's business | unchanged |
| make-prompt's `Bash(git *)`; every one-program entry with a trailing `*` | pre-approved | **unchanged: stated** |
| A rule is text: the same command in another spelling | covered by `bash *` | **not pre-approved: it asks.** The safe direction, and E1d counts how often the model does it |

## 3. Rules for every feature
- Frozen: `RULE_NAMES` (`bash-guard.py:162`), `GATE_NAMES` (`:167`), `FLOOR` (`:171`), `KNOWN_RULES` (`heartbeat.py:79`), `hooks/hooks.json`, `py.sh`, `all.sh` NAMES (`all.sh:20`), `ci.yml` steps, `fit_key` in six hooks, `long_form` and `counter_in` in two. A builder who finds one must change stops and asks.
- Never touched: `.claude/*.local.md`, the private terms file (never read, never printed), `.agents/`, `.codex/`. Stage by file name. Test terms, task names and paths are invented.
- **Any deny ends that action.** A guard, a refused permission, a hook: do not retry it, rephrase it or move it into a script file; report it. E1's probes are expected to be refused; a refusal there is the result.
- A bug gets its failing case first, shown red on `f4b56fb`, then the fix. A check that is green on the base is shown red by a mutation. Every "as today" claim in a builder brief carries a file:line the builder has read.
- **A launcher rule names three things:** the launcher, one hook script and one option word. Never the launcher alone: `py.sh` passes `-c` on (`py.sh:47–49`).
- **A rule is copied from the command, never typed fresh.** The rule and the `!` line carry the same variable and the same quotes, so the same substitution makes them equal.
- **The real settings are never loaded and never written.** No command of E1, S1 or a test names a Claude Code settings file. The headless runs leave the user's settings out (`--setting-sources project`) and give the hooks a temp `HOME`.
- **Controls before variants.** E1 proves first that today's grant renders and that no grant aborts. A harness that cannot tell them apart proves nothing.
- A result names its switches: the Claude Code version, the OS build, the Git Bash version, the permission mode, the settings sources, the model. A result is claimed for those only; every other build is "assumed".
- An unknown is never a number in code. E1's counts go into §10 and the release notes.
- Import allowlists: `wait-gate-test.sh:983`, `recall-test.sh:218`, `paid-guard-test.sh:80–81`, `fresh-gate-test.sh:1174`, and the eight-file standard-library check in `heartbeat-test.sh` (s1). No feature adds an import; `ledger.py:67` stays as it is.
- The view reads the ledger as data anyone may have written: a bad line is skipped and counted, a field is cleaned before it is printed, nothing is created, nothing is guessed.
- One heavy job at a time on the laptop, across all builders, at low priority; suites one at a time; never `all.sh` there. Claude Code stops a background suite when memory runs low: report it, restart only on the maintainer's word.
- After a merge's automated security review: classify each finding against the class list of `SECURITY.md` first; one fix round, then report.
- Public repo: no personal path, user name or real task name in a plan, a test, a doc or the mock that is committed.
