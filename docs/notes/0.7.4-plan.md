### F1 · the paid check sees a counter in the other folder at any length (lane A, after E1 · half a day, plus R1) — the must-have
- **Evidence.**
  - A project whose key is too long for its folder has two possible state folders, full key and short key (`bash-guard.py:2943–2950`).
  - With long paths off, `fit_key` sends a project with a full-key folder past 232 characters to the short key, whatever either folder holds (`:2056–2060`).
  - The paid check looks for a counter in the other folder twice: before counting (`paid_two_counters`, `:2953–2960`, called at `:3308`) and again under the counter lock (`:3149–3153`). Both use a plain `os.path.isfile`.
  - Measured (0.7.3 E1, `docs/notes/0.7.3-plan.md:267–273`): at 240 and 244 characters the plain call sees the counter and the paid call is refused. At 245, 250 and 270 the counter's own path passes 259, `isfile` says false, the call is allowed and `used` is 1 in the short folder. The long form saw the counter at every length (`:275`).
  - Microsoft documents the form: it turns path parsing off, so no `/`, `.` or `..`; it cannot be relative; a share is `\\?\UNC\server\share`; one name may hold about 255 characters (§7).
- **Fix.** Two small functions beside `paid_keys`, then two call sites.
  - *New* `long_form(p, nt)`: pure text, no file call, never raises. `nt` false gives `""`. `/` counts as `\`. `C:\a\b` gives `\\?\C:\a\b`; `\\srv\sh\a` gives `\\?\UNC\srv\sh\a`; a path already in the long form is returned as it is. Anything else gives `""`: a relative or drive-relative path, a device path (`\\.\`), or a path with an empty, `.` or `..` part.
  - *New* `counter_in(base, name, nt)`: true when `base/name/paid-runs.json` is a file by the plain path, or by its long form when there is one.
    ```python
    p = base + os.sep + name + os.sep + "paid-runs.json"
    if os.path.isfile(p):
        return True
    x = long_form(p, nt)
    return bool(x) and os.path.isfile(x)
    ```
  - `paid_two_counters` (`:2959–2960`) and the test under the lock (`:3152`) call `counter_in`.
  - **Why this is safe to add.** The plain look runs first and is unchanged, so no layout refused today is allowed tomorrow. The second look can only turn "no counter" into "a counter", so an allow into a refusal. Every part after the base is a sanitised key (`[A-Za-z0-9._-]`, `:2948`) or a literal, and the base comes from the hook's own `HOME` (`:3239–3243`), so no text from a command or an adapter reaches the long form. A base `long_form` cannot spell gets the plain look only, as today.
  - The result is the refusal the 233 to 244 window already gives (`paid-guard-test.sh:2296`), now at every length the folder can have.
- **Acceptance (the user does).**
  1. On Windows with long paths off, in a project whose 250-character full-key state folder holds `paid-runs.json`, the user asks for a paid run with an adapter go. It is refused, the reason names `/smartuse:doctor`, nothing is counted, and the short folder holds no counter. Today it is allowed.
  2. The same at 245 and at 270 characters.
  3. On a machine where the miss already happened (a counter in both folders), the paid run is refused with "two state folders hold a counter".
  4. In an ordinary project a paid run is counted as today: used 1, then 2.

## 9. Risks
- **A new refusal where there was none.** A folder that only the long form can see (a name ending in a dot, a stale 250-character folder) now refuses paid runs. That is the point; doctor names both folders and the way out.
- **After the update, a past miss is refused** (D-YK32). It needs an administrator to have switched long paths off over a counter in a folder of 245 characters or more, so it should be rare.
- **Spellings of `HOME` the long form does not cover.** A relative `HOME`, or one with a `..` part, gets the plain look only: today's behaviour, no worse. A mapped drive or a share is assumed to work as Microsoft documents; E1b tries a share only if one is reachable.
- **Pinned texts move.** F3 changes the words of §39e and §39f and the tails at `paid-guard-test.sh:658` and `:667`. Each is shown red first and changed in the same commit as its code.
- **Windows-only proof.** §39g and h5 to h7 need Windows and `LongPathsEnabled` = 0. CI's Windows runner is assumed to have long paths on, so those cases skip there and the laptop is their only proof. §39h, §39i, h8 and r1 to r5 run everywhere.
- **Two files, one text.** A later edit of one helper fails h8 until the other follows. The failure message says which file.
- **"Too long" by error class.** A folder deleted mid-call can raise the same error as a name that does not fit. The words would then be wrong once; doctor's next run says the truth.
- **F4a may still fail under heavier load.** Then the fix is the case's clock (start it after the push), not a wider number a second time.
- **Laptop time.** E1 (under 30 minutes), three `paid-guard-test.sh` runs (about 15 minutes each at low priority), two `run.sh` runs (about 10 each), one T2 (about 45), a second T2 if R1 moves code. Claude Code has stopped suites on low memory before; restart only on the maintainer's word.
- **E1 makes folders longer than Windows tools like.** A failed cleanup leaves a folder in the temp area; it is listed, not forced.
