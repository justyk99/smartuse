# recall: "the summary is not a source" (0.6.0 design and build contract, 2026-11-08)

Status: plan approved by YK on 2026-11-08. This note is the contract the builders work from (dev-flow phase 3); F4 turns it into the user docs. Every existing name below was grepped on the dev branch; new names are marked *new*.

## The problem (the class, not a case)
A long session gets compacted. Claude keeps a model-written summary and loses the exact words. Two failures follow:
- **Gone:** the owner's exact words and the job's details are not in context any more.
- **Present but not used:** the job's real files are on disk, but Claude works from the summary or from notes, and still says "checked".

Claude Code already reloads CLAUDE.md, auto memory and up to 5 recently modified files after a compaction. It does not know which files are this job's sources, and nothing refuses an action taken from the summary. Memory plugins put text back into context; none refuses a send. smartuse adds the refusal and the pointer, never a store.

## What ships in 0.6.0
| Feature | What the owner sees |
|---|---|
| F1 fresh-source gate | a `publish:` command or a `publish_tools:` tool call is denied until every `sources:` file has a Read in this session after the last compaction; the reason names the unopened files |
| F2 recall at the squeeze | PreCompact hands the summarizer the source list and the owner's last prompts verbatim; after the squeeze Claude is told "the summary is not a source" and which files to re-open; the status line counts squeezes |
| F3 recall at session start | `handoff:` names the handoff file; its first lines and its age are printed on startup, clear and resume |
| F4 docs, counts, a 30-second demo with invented files | README, SECURITY, CHANGELOG, this note |

## Adapter keys (in the human-only `.claude/smartuse.local.md`)
One line per key, `key: value, value`, first occurrence wins, frontmatter or body; values split on commas, trimmed, empty ones dropped. Read the way `until-done.py` `adapter_check()` reads `check:`. The project dir is `CLAUDE_PROJECT_DIR`, else the event's `cwd` (`native_path`), else the process cwd (the order of `until-done.py` main).
| Key *new* | Value | Example |
|---|---|---|
| `sources:` | paths or globs, relative to the project dir or absolute | `sources: jobs/demo/plan.pdf, jobs/demo/photos/*.jpg` |
| `publish:` | shell command patterns: a pattern matches a command segment whose words start with the pattern's words | `publish: python send.py, git push` |
| `publish_tools:` | tool names, `fnmatch` globs | `publish_tools: mcp__*__file_upload, mcp__*__upload_image` |
| `handoff:` | one path (F3) | `handoff: docs/STATUS.md` |
No `sources:` → no gate, no change for that repo. `sources:` without `publish:` and `publish_tools:` → no gate; F2/F3 say once that nothing is gated.

## F1: what "opened" means
- A **Read** is an assistant record whose `message.content` holds `{"type":"tool_use","name":"Read","input":{"file_path":…}}`. Records with `isSidechain: true` are skipped (a subagent's read is not the model's). Bash `cat` or `head` does not count (documented). A Read whose result record (a `tool_result` block with the same `tool_use_id`, outside a sidechain) says `"is_error": true` does not count: a missing file and a Read the permission rules denied are both "not opened"; a later Read of the same path that works counts. A Read with no result record counts (documented).
- The **last compaction** is the last record `{"type":"system","subtype":"compact_boundary"}`; a `user` record with `isCompactSummary: true` is the fallback marker. No marker → every Read in the session counts.
- **Path equality:** both sides through `native_path`, made absolute (a relative source against the project dir), `os.path.normpath`, `os.path.normcase`, backslashes to `/`. `C:\x\plan.pdf` and `C:/x/plan.pdf` are the same file.
- **Globs** are expanded on disk at check time (the link-safe walk below, sorted), and only for patterns relative to the project dir; an absolute source is taken literally. A pattern that matches no file → deny with its own reason (a typo must reach the owner). More than 200 files after expansion → deny "narrow the pattern".
- **Plain local paths only:** the adapter can arrive with a cloned repo, so a source value (after `native_path`) is accepted only in a plain local spelling: relative with no leading separator, no drive and no `..` part; `X:\…` or `X:/…` (not `X://`); or `/…` (not `//` or `/\`). Any value holding `\??\`, `\\?\`, `\\.\`, `//?/`, `//./` or `GLOBALROOT` (any case) is refused. The automount prefixes `/net/` and `/Network/` are refused too. Anything else is never expanded, stat'ed or compared; a matching publish is denied with its own reason. A part after a leading drive that holds `:` (a drive letter in the middle, an NTFS stream) is refused, and so is a part made only of dots and spaces (other than `.` and `..`): Windows reads those as another drive, a stream or the folder before them. The text check runs before any filesystem call. Hooks never touch the network. A mapped network drive letter cannot be told from a local one by its text and is accepted (documented).
- **Links are refused, never followed:** a relative pattern is expanded component by component with `lstat` and `os.scandir` (no `glob`, so the project path is never read as a pattern), keeping `glob`'s rules: `**` matches zero or more folder levels (as `glob(recursive=True)` did), hidden names only when the part starts with `.`. A component, a matched entry or a folder the `**` walk would enter that is a link denies with its own reason. On Windows a link is a symlink or a reparse point whose tag has the name-surrogate bit (junctions, mount points); cloud-sync placeholders (OneDrive) carry other tags and stay ordinary files. An absolute source is the owner's literal path and is followed as written. A relative source that holds `[`, `*` or `?` and also exists as a literal file stands for both: the literal file and the wildcard matches are all required (a source is never missed).
- **One deadline:** `BUDGET_S = 4.0` from the start of the hook (it starts before the heredoc scan, so a command that keeps the scan busy cannot use up the time the check needs), shared by the source expansion and the transcript pass. The expansion runs in a daemon worker thread joined with the time left (as `file-guard.py` `resolved()` does for realpath); a worker that does not answer is left behind and the process ends with `os._exit(0)` after its output is flushed. Past the deadline at either step a matched publish is denied, never let through: a hook that times out lets the call through, so the deadline sits inside the hook.
- **Transcript pass:** one forward pass; `json.loads` only on lines that contain `"tool_use"`, `compact_boundary` or `isCompactSummary`; the deadline is checked every 128 lines and at the end. The `transcript_path` comes from the event. Measure the pass on the laptop (a session-sized log and the largest `.jsonl` under `~/.claude/projects`, sizes only) before any number is quoted.

## F1: what a publish is
- **Bash:** after the existing `RULES` loop allows the command. `strip_heredocs(cmd)` first (a data body is not a command; a body that a shell or interpreter runs from stdin stays, as today). Split on newlines, `;`, `&&`, `||`, `|`. Per segment find the command word: skip leading `VAR=value` words, the `if` / `then` / `do` of a compound, and the programs that only run what follows them, with their options (`command`, `builtin`, `exec`, `env`, `nohup`, `nice`, `timeout` and its duration, `stdbuf`, `xargs`, `time`, `sudo`, `doas`). A segment matches a pattern when the pattern's first word is the command word and each later pattern word appears, in order, among the command's later words: `git push` matches `git -C dir push origin`, `python send.py` matches `python -u send.py`. Words compare case-sensitively, except: a pattern word that names a file (holds a separator or ends in `.<ext>`) matches a command word whose path components end with its components, case-insensitively (`send.py` matches `C:/proj/send.py` and `../send.py`; `tools/send.py` does not match `send.py`); a leading `/x/` reads as the drive `x:` (Git Bash's spelling); the command word compares by its last path component without `.exe` (`/usr/bin/git`, `git.exe`); and `python`, `python3`, `python3.N` and `py` are one name. The body of `$(…)` and of backticks (inside double quotes too, not inside single quotes; heredocs in a body stripped first, so Claude Code's `git commit -m "$(cat <<'EOF' …)"` form stays data) is checked the same way, to depth 2. A string handed to another shell (`sh|bash|zsh|dash|ksh -c`, `eval`) is no longer read into: since the security review the command counts as a send while the sources are unopened (see "a command the gate cannot read", below). Inside an unquoted-delimiter heredoc (`<<EOF`) bash still runs `$( )` and backticks, so those bodies are checked too, at the top level and inside a body; the heredoc's plain lines stay data. `echo "python send.py"` is not a match (its command word is `echo`). A pattern word that only happens to appear later (`git log --grep push`) is an over-deny, which costs one turn.
- **More spellings (security review, 0.6.0):** command names compare without regard to case on every OS (`GIT push` on Linux is an accepted over-deny), and `.exe`, `.cmd`, `.bat`, `.ps1` and `.com` are dropped from a command's name. `pythonw` and `pyw` are `python`. The last part of a path is read the Windows way: a trailing dot or space and a `:stream` are dropped (`send.py.`, `'send.py '` and `send.py::$DATA` are `send.py`). A backslash-newline joins lines without a space. More programs that only run what follows them are read through: `setsid`, `busybox`, `coproc`, and the package runners `uv run`, `poetry run`, `pdm run`, `pipenv run`, `hatch run`, `rye run` and `pipx run`. More shells count as shells: `ash`, `fish`, and `$SHELL` (an unknown shell is read as a shell: it fails closed). A here-string given to a shell (`bash <<< 'git push'`) and the text an `echo` or `printf` pipes into a shell (`echo git push | bash`) are checked as commands. `git -c alias.NAME=VALUE` adds VALUE's words to the git command, so `git -c alias.p=push p` is `git push`.
- **Heredoc scans are bounded:** the two heredoc scans (`HEREDOC`, the frozen `strip_heredocs`, and the gate's own opener scan) rescan their text once per unclosed opener, and `HEREDOC` also backtracks once per delimiter character, so a crafted command could keep them busy past the hook's timeout. A command with more than `HEREDOC_CAP` (16) `<<` openers, an opener whose delimiter is longer than `HEREDOC_DELIM_MAX` (64), or openers whose delimiter lengths times the text length pass `HEREDOC_BUDGET`, is not scanned for heredocs: `many_heredocs()` is checked first and every line of the text is read as code, by the older RULES too. The budget is spent once per command (nested bodies inherit the decision). That is an over-deny, never a miss (17 heredocs with `sudo` in a data body are denied; one turn). While the sources are unopened such a command is also one the gate cannot read, so it counts as a send (below). `HEREDOC`, `strip_heredocs` and `STATE_CALL` stay byte-identical: the checks sit in front of them (`STATE_SHAPE` is the cheap look before `STATE_CALL`; a state-write text it does not accept is not stripped, so it is read as it stands). The fail-closed deadline starts at the top of `main()`, before any of these scans.
- **PowerShell (security review, 0.6.0):** `hooks.json` registers the one shell entry with the matcher `Bash|PowerShell` (the PowerShell tool is on by default on Windows for claude.ai accounts; `CLAUDE_CODE_USE_POWERSHELL_TOOL=0` turns it off). The hook gets the text in `tool_input.command`, the same field as Bash. A state write typed into PowerShell goes through the same `STATE_CALL` strip. The text is normalised by `ps_text()` (a backtick-newline joins lines, an escaped quote or backtick is dropped, any other backtick is removed, here-string fences become line breaks, `{` and `}` become `;`, commas become blanks) and the older RULES run on that text as the regexes they are: `git push --force`, `sudo` and a credential-file read are denied through PowerShell too. The gate's match is coarse: the pattern's first word may be **any word of a statement** (PowerShell puts the program after a parameter: `Start-Process -ArgumentList push -FilePath git`), and the later pattern words follow it in order. A form it cannot read (typographic quotes or dashes, an escaped quote, a block comment, a `Start-Process` word, a string handed to another shell) counts as a send while the sources are unopened. It is not claimed to read every PowerShell tokenisation; an adversarial tokenisation pass is listed for 0.6.1. `Start-Process`, `saps`, `start` and `wsl` are read like the Bash wrappers; a string piped into `iex` from an `echo` or `printf` is checked; script blocks (`if ($ok) { git push }`) are statements. A string handed to another shell (`cmd /c` or `/k`, `pwsh` / `powershell -c` / `-Command` / `-EncodedCommand`, `iex "…"` / `Invoke-Expression`) is not read into: the command counts as a send while the sources are unopened. An `-EncodedCommand` value that is not base64 of UTF-16LE text is denied with its own reason (below). Typographic quotes and dashes (PowerShell reads them as plain ones) and an escaped quote are also commands the gate does not try to read (below). An adversarial pass over PowerShell tokenisation has not been done (ROADMAP). A PowerShell text is also read one line at a time, so an apostrophe in a data line cannot hide the lines after it. Over-denies of the accepted kind: an unquoted `Write-Host git push`, `Select-String python send.py`, a publish word in a data here-string or an array, or on its own line inside a multi-line quoted PowerShell argument. The quoted `Write-Host "git push"` is allowed. A `Monitor` call's command reaches a `Bash` matcher as a Bash call from Claude Code 2.1.314 on, so it is covered by the same entry (confirmed live on 2.1.321); a WebSocket watch has no command and fires no Bash hook.
- **Tools:** `hooks.json` gains one PreToolUse entry, matcher `mcp__.*(upload|send|publish|post|share|submit).*`, command bash-guard.py, timeout 10. In bash-guard `main()`, a non-Bash event runs only the fresh-source check, and only when the tool name matches a `publish_tools:` glob; anything else is allowed. A `publish_tools:` entry the matcher cannot reach is named by F2/F3 as "not gated". A click on a page's own Send button is not gated (documented).

## F1: fail open, fail closed
Detection errors (bad stdin, unreadable adapter, no `sources:`) → allow, as today. **After a publish match**, any failure to verify (transcript missing or unreadable, past the deadline) → deny. A missed deny ships a wrong deliverable; a wrong deny costs one turn.

**A command the gate cannot read counts as a send while sources are unopened** (security review, 0.6.0; this replaces "no publish match → allow" for such commands). Five review rounds each found new crafted-command classes, several caused by the previous fix, so reading quoting ever deeper was given up. A sixth round reviewed the new rule and found no regression; a seventh reviewed a further fix round, found regressions in it, and that round was reverted. `complexity()` (linear, run on the command before any heredoc stripping, RULES or scan) returns a tag for a command past a fixed size (over `COMPLEX_MAX`, 32 KB), a command past the heredoc scan cap, bound or budget, `COMPLEX_SUBST` (3) or more command substitutions outside data heredocs, and, in PowerShell, typographic quotes or dashes, an escaped quote, a block comment (`<#` anywhere), or `Start-Process` (`start`, `saps`) as a whole word anywhere (its arguments are not read: they can be grouped by parentheses, an array, a here-string or one quoted string); the scan tags a string handed to another shell, in exactly these forms: `bash` / `sh` … `-c`, `eval`, `iex "…"`, `cmd /c` (and `/k`), `pwsh` / `powershell -c` / `-Command` / `-EncodedCommand`. Other ways of handing a command to another shell are not recognised yet (see the limits below). With `sources:` and `publish:` listed, a tagged command goes straight to the source check and is denied while a source is unopened; the reason adds: `The command is also too complex for the source check to read (<tag>), so it counts as a send: open each with Read, then retry, or simplify it.` A tagged command counts as a send only when the adapter lists `publish:`. Once the sources are opened, the tagged command is read as before: it falls through to RULES and is not scanned for a publish. Cost: an unusual but harmless command, right after a compaction and before the sources are re-read, is denied once.

**Order.** For an ordinary command RULES run first, so a RULES match keeps its own reason. For a tagged command, and for any command over `RULES_FIRST_MAX` (4,096) characters, the source check runs first: the frozen RULES patterns cost time quadratic in the text on a dense run of command words, past the hook timeout, and a timed-out hook lets the call through.

## F2 and F3: `hooks/recall.py` *new*
Registered on `PreCompact` (matcher `manual|auto`) and `SessionStart` (no matcher), timeout 10. Python 3.9 stdlib, no subprocess, no network, exit 0 always, prints nothing on bad stdin. Everything printed is scrubbed first and capped at 9,000 characters (cut, never spilled to a file).
- **Owner prompts:** `user` records whose `turnOrigin` or `origin.kind` is in `{"human","sdk"}`, not `isMeta`, not `isCompactSummary`, not starting with a harness marker: copy `wait-gate.py`'s `HUMAN`, `INJECTED`, `is_human()` and `text_of()` rules (no import between hooks). The last 8, oldest first, whitespace collapsed, each cut at 300 characters.
- **Scrub:** token prefixes with a word boundary (`\b(sk-|ghp_|gho_|github_pat_|xox[abpr]-|AKIA|AIza)[A-Za-z0-9_-]{8,}` → `[secret]`), digit runs of 8 or more → `[number]`, e-mail addresses → `[email]`. The scrub is linear in the text (`scrub_email()` finds each `@` and walks back over the local part; a text with no `@` is not scanned), and a prompt or handoff line is cut to the printed length plus 4,096 characters before it is scrubbed, so a pasted blob costs no more than a line. Path values (each `sources:` entry, the handoff name, the not-gated entries) use a narrower digit rule, free-standing runs only (not glued to a letter, digit, `_`, `/`, `\`, `.` or `-`, not followed by a file extension), so `photos/IMG_20261108_140233.jpg` prints intact; owner prompts, handoff lines and custom instructions keep the full rule (review findings 2026-11-08). `task-folder` stays as it is.
- **PreCompact** (F2) prints instructions for the summary: keep these source paths verbatim; keep these owner prompts verbatim; mark anything not re-verified as "from summary". When the input carries `custom_instructions`, they are printed first. Claude Code uses a PreCompact hook's stdout as instructions for the compaction summary and cuts it at 10,000 characters (hooks reference, "PreCompact output", checked 2026-11-08); whether it is added to the owner's `/compact` text or replaces it is not documented, so the owner's text is echoed (scrubbed) to survive either way. The live `/compact` run settles it.
- **SessionStart `compact`** (F2) prints: the squeeze time, `The summary is not a source.`, the `sources:` list with "none counts as opened now; open each before any output", and the owner prompts. Without `sources:`: two lines (time, the sentence).
- **The handoff file is contained:** read only when it is a relative path with no `..` part, not a network or device path, with no link among its components (symlinks and name-surrogate reparse points, checked with `lstat`, never followed), resolved inside the project dir, and a regular file (64 KB read cap); otherwise one line says it is not read. A `.git` file's `gitdir:` that is not a plain local spelling (or is under `/net/` or `/Network/` once normalised, raw or joined to its base) skips the stale check, and so does a `.git`, git dir, `logs` or `logs/HEAD` that is a link. A relative gitdir is walked component by component from its base; an absolute gitdir's ancestors are not (they are the owner's own folders, and `/var` on macOS is itself a link). The text checks run before any filesystem call.
- **SessionStart `startup` / `clear` / `resume`** (F3): with `handoff:`, its first 15 lines, its modified time, and `stale: the handoff is N days older than the last commit` when `.git/logs/HEAD`'s last entry is newer (a file read). On `resume` with a compaction in the transcript: `resumed; the compacted part is a summary, not a source`. With `sources:`: the list and "open each before any output". Neither key → nothing.
- **State** *new*: `~/.claude/smartuse/projects/<key>/recall.json` `{compactions, last_at, last_unopened: [...]}`, key and dir as `ledger.py` computes them (asserted equal in the test). Counts and paths only, never a command.
- **Counter** (F2): `heartbeat.py` `apply()` on SessionStart `compact` of the same session: `compactions += 1`, `compact_at`; `--line` adds ` · squeezed N× (last HH:MM)` while it is above 0.

## Honest limits (for the README)
A Read is counted, not understood. The summary's quality is the model's. A click on a page's Send button is not gated; uploads and named commands are. Only tools whose names the `mcp__…(upload|send|publish|post|share|submit)…` matcher reaches are gated; a `publish_tools:` entry outside it is named "not gated" at session start. A publish hidden inside another program (`python -c`, a script that calls the send, `xargs` given the script name on stdin, `env -S`) is not seen; the wrappers listed above are. A mapped network drive letter is accepted as local, and an absolute source is followed as the owner wrote it. A `**` pattern refuses any link in the tree it walks (a link file cannot be told from a linked folder without following it), and a `*` part that matches a link refuses too: `**/*.pdf` at the root of a repo with a Python `venv/` or npm workspace links, or `jobs/*/plan.pdf` beside a `jobs/latest` link, is refused with the link named. Such a repo needs a pattern that names the job's folder. An `@` in a path value still prints as `[email]`. A heredoc whose delimiter is partly quoted or holds non-word characters is read shorter than bash reads it (old code, on the must-not-change list), so a command crafted that way can hide a publish. Real over-denies of the accepted kind: `git stash push`, `git help push`, `python -m py_compile send.py`, an unrelated script with the same name.

A text gate cannot see a command that is built at run time (variables, brace or glob expansion, `$'…'` quoting): the text it reads is not the text that runs. This is the class the closing rule above narrows but cannot close. A command in a class the gate knows it cannot read is denied while the sources are unopened (over-deny, one turn).

Some other ways of handing a command to another shell or interpreter are not yet recognised as such (other spellings of the same launchers, text fed on standard input, process substitution, shell functions and traps); they are listed for 0.6.1.

In Bash, the join of a line that ends in a backslash (`command_segments`) does not check what comes before that backslash, so the line after an escaped backslash, or after a comment that ends in a backslash, can be misread. Present before the security batch; listed for 0.6.1.

PowerShell, not seen: a write verb on the human-only files (`Set-Content`, `Out-File`, `Add-Content`, `Copy-Item`, `Move-Item`, `New-Item`, `Remove-Item`, `[IO.File]::…`; the same known gap as the Bash side, ROADMAP), a download that is then run, and the body of a `-File` script (planned for 0.7.0). The older rules that need a Bash word (`Remove-Item -Recurse -Force` of a root, a download piped to `iex`) have no PowerShell form yet. The PowerShell match is coarse, so these are over-denies of the accepted kind, one turn each: an unquoted `Write-Host git push`, a publish word in a data here-string or an array, or on its own line inside a multi-line quoted PowerShell argument. An adversarial pass over PowerShell tokenisation has not been done (planned for 0.6.1).

Accepted over-denies of the closing rule: right after a compaction, before the sources are re-read, an unusual but harmless command in a tagged class (a long script, a command with several substitutions, a `bash -c` string, heredocs past the cap, PowerShell typographic quotes, a block comment, a `Start-Process`, `saps` or `start` word anywhere, `npm start` and a quoted mention included) is denied once, right after a compaction or before the sources are first opened, until the sources are re-read; a backtick escape inside that word is not caught yet (0.6.1); the reason says to open the sources or simplify the command.

Pinned known limit, on Bash at or under the heredoc cap: a quoted word that spans lines is read whole, so lines inside it are read as part of that word. It was left as it is because reading such text line by line flipped seven existing allows (quoted commit messages and PR bodies); it needs quote-aware per-line handling (ROADMAP 0.7.0).

Time: the fail-closed deadline covers the whole hook from its start, the heredoc scans are bounded, and a command the gate cannot read is decided before any scan of it, so the command's own scan can no longer outrun the hook's timeout; the measured case (8,000 openers, 48 KB) is in the README. Two limits remain. The frozen older RULES patterns are slow on a very long, dense run of command words; a command over `RULES_FIRST_MAX` characters has the source check first, but when the sources are opened, or no adapter is present, such a command reaches RULES and can outlast the hook timeout, and a timed-out hook lets the call through (ROADMAP: every rule linear). And a hook that is slow to start, beyond about 6 s, is outside every deadline in it. A subagent's hook may get its own transcript; v1 checks the transcript it is given. A hook that does not finish inside Claude Code's timeout (a very slow interpreter start) lets the call through. Transcript records are internal to Claude Code and change between versions; the fixtures carry each shape seen.
