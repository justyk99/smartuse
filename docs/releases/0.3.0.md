**What's new**

- **A receipt per plan step.** `run-plan` splits a kickoff into steps (judgment / build / mechanical / verify) and now every step carries its own receipt: which tier and model ran it and why, whether you overrode the tier, whether it passed, whether it escalated, what the fresh-agent review said, and the agent's *real* API calls and tokens. The tokens come from a `SubagentStop` hook that reads the agent's transcript — nothing is estimated, and when the hook cannot tell which step an agent belongs to it leaves the receipt unattached rather than guess.
- **`/smartuse:receipts`** shows the table for the latest run, `/smartuse:receipts <task>` for a closed one (runs are archived by the Stop hook), `all` for every run. Zero model tokens to compute.
- **`run-plan --until-done`**, the loop that does not stop for "go": a deterministic Stop gate refuses to end the turn while steps or the repo's `check:` command are unfinished, and lets go only for a real human question, a double failure, a rule gate, or the cap. The check command is read from a human-only adapter file, screened by `bash-guard`, limited to fixed shapes or a root-pinned script, and never taken from anything the model writes.
- **`file-guard`** hook: the adapter and the pin file are read-only for the model.

**Measured** (bench repo, Claude Code 2.1.300, Max plan): one line → kickoff 14/14 → endpoint + 4 tests built (11/11) → verified end to end → stopped with a precise human question. $1.30, 5.6 min, 19 turns. The receipts for that run are in `bench/results-example/`.

**Upgrade:** `/plugin install smartuse --marketplace justyk99/smartuse` (or `claude plugin update smartuse@smartuse`). State stays under `~/.claude/smartuse/`, never in your repo. Existing `receipts.jsonl` files keep working; the per-step join applies to runs started on 0.3.0.

**Tests:** bash-guard 44 · file-guard 4 · ledger + receipts 13 · until-done 23 — all green in CI, plus `claude plugin validate --strict` on plugin and marketplace.

**Honest limits:** the routed-vs-not A/B over 20 real tasks is still not measured; the ledger and the per-step receipts exist so that number has a line of evidence per step when it is published. Skills are instructions; the hooks are the only enforcement.
