**What's new in 0.5.0 — "one session that delegates"**

- **Waiting or stopped — the status line says which.** A session that hands work to another one and has nothing armed to wake it is not waiting, it is stopped. The new wait gate (a Stop hook, 0 tokens) blocks that turn once and asks for a watcher or an honest `STOPPED: nothing will wake me; <who> must.` The status line then shows `STOPPED · handed off 20:41 (builder) — nothing will wake this session`, or `waiting on builder · watcher armed 20:41`. Built from a real incident: a "step done" message that never arrived, and a session that sat idle believing it was waiting.
- **`hooks/watch.py`, the watcher.** Run it in the background after a hand-off: `--git <remote> <branch> --path <result file> --since <commit>` wakes the session on the push, `--file` on a file. 0 model tokens while waiting; `--max` (default 4 h) and three failed polls in a row end it with an exit code, so the session is woken either way, never a silent spin.
- **One session, steered there.** make-prompt's kickoff now says where the work runs (`Runs on: <this machine | the machine with X>`). When that is another machine, the hand-off says to run the kickoff there as one session with run-plan, and promises no ping. run-plan checks first that every tool and input file a step needs is on this machine. A step that fails shows `needs-machine: <tool> not found here` and does not start; when most fail, it stops with `Run this plan on <machine>`. A new `command` tier runs one shell command (a render, a conversion) as a background task, with no model and no agent tokens.
- **The until-done loop and long commands.** While a `command` step runs in the background, the loop lets the turn end; the command's end notification wakes the session. It used to spend all 6 blocks on a long render and switch itself off.
- **Faster hooks on Windows.** The launcher remembers the Python it proved, so each hook event starts Python once (it used to start it twice, plus the Microsoft Store stub on Windows). The author's laptop went from about 2.0 s to 0.5–1.8 s per hook call; Linux from ~78 to ~57 ms per heartbeat event.
