**What's new in 0.4.0 — "is it working, or waiting on me?"**

- **Heartbeat.** `/smartuse:status` prints one deterministic line: `working · waiting on agent: general-purpose 4m12s · step 3/6 build·opus "tests"`, or `waiting on you · 3m`, or `NEEDS YOU: which rounding rule?`, or `stalled? no activity 6m`. Hooks on every tool call, agent start and stop, prompt, stop and notification write it; nothing is estimated and no model tokens are spent. `/smartuse:status install` puts it in your terminal status line with model, context % and cost; the plugin also ships a `subagentStatusLine` that names the plan step on each agent row (shipped, not yet seen working in a live session).
- **The until-done loop now really holds.** In 0.3.0 the Stop gate let the turn end on the second Stop of every prompt (it trusted Claude Code's `stop_hook_active` flag), so `--until-done` pushed once and then gave up. It now holds until the steps and the repo's check are done, a step needs you, or it has blocked `max_blocks` times (6).
- **Measured: routed vs not.** `bench/ab.sh` runs one kickoff and then `run-plan --until-done` under each routing dial on fresh copies, and compares them from the hook archives. On 4 bench asks with Opus pinned, both routed dials cut the median cost by **24 %**. They did not cut agent output (the cheaper models wrote more), 11 of 12 runs ended with green tests, and one aggressive run left 3 failing tests. n=4 on one small repo: a direction, not a promise. Every row has its receipts in `bench/results-example/2026-10-22-ab-run3/`.
- **Receipts by model.** Every plan step carries its agent tokens per model; the summary line gives each model's share of agent output (`haiku 45% · fable 40% · sonnet 13%`). `/smartuse:receipts --json` for scripts.
- **Windows.** On a stock install `python3` is the Microsoft Store stub, so no hook had ever run there. Every hook now goes through `hooks/py.sh`, which picks a working interpreter; hooks read their input as UTF-8 (a non-ASCII character used to make bash-guard fail open under the Windows code page); the check runner finds `npm`/`pnpm`/`yarn`; files are checked out with LF. CI runs on Linux, macOS and Windows, and on Python 3.9 and 3.12.
- **Safer guards.** bash-guard now also denies `sudo` inside if/for/subshells/`bash -c`, `bash -c "$(curl …)"` and `bash <(curl …)`, `git -C … push --force`, `+refspec` and `--mirror`, and credential files by name (SSH keys, `.aws/credentials`, `.npmrc`, `.kube/config`, the Claude credentials file), including Windows spellings. file-guard is case-insensitive and path-normalised.
- **State per repository.** Receipts, the gate and the heartbeat are keyed by the repository's full path, so two folders with the same name no longer share state. 0.3.0's folder-name dir is never written again; `/smartuse:receipts` still shows its runs, marked as shared.
- **Skills.** make-prompt hands off with a paste-ready `/smartuse:run-plan` line; an open question the kickoff already answers with an `assumed:` default no longer blocks run-plan; living-docs writes its ledger receipt; the receipts and ledger arguments reach the tool (`$ARGUMENTS`); three new eval cases (ledger-empty, status-line, run-plan-no-task).
