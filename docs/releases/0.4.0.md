**What's new in 0.4.0 — "is it working, or waiting on me?"**

- **Heartbeat.** `/smartuse:status` prints one deterministic line: `working · waiting on agent: general-purpose 4m12s · step 3/6 build·opus "tests"`, or `waiting on you · 3m`, or `NEEDS YOU: which rounding rule?`, or `stalled? no activity 6m`. Hooks on every tool call, agent start and stop, prompt, stop and notification write it; nothing is estimated and no model tokens are spent. `/smartuse:status install` puts it in your terminal status line with model, context % and cost; each agent row in the UI names its plan step.
- **Receipts by model.** Every plan step now carries its agent tokens per model, and the summary line says the share of agent output per model (`haiku 45% · fable 40% · sonnet 13%`). `/smartuse:receipts --json` for scripts.
- **The A/B runner.** `bench/ab.sh` runs one kickoff and then `run-plan --until-done` under each routing dial on fresh copies, and prints the comparison from the hook archives. Its first real run caught a run-plan defect (two dials stopped on an assumed value) before any number was published; the fix and the evidence are in the repo.
- **Windows.** On a stock Windows install `python3` is the Microsoft Store stub, so no hook had ever run there. Every hook now goes through `hooks/py.sh`, which picks a working interpreter; `HOME` is honoured under Git Bash.
- run-plan: an open question the kickoff already answers with an `assumed:` default is not a blocker.

**Tests:** bash-guard 48 · file-guard 4 · ledger + receipts 17 · until-done 23 · heartbeat 55 · A/B dry run — green in CI, plus `claude plugin validate --strict`.

**Upgrade:** `claude plugin update smartuse@smartuse`. State stays under `~/.claude/smartuse/`. Windows users: Git Bash is required for the hooks (Claude Code runs hook commands through it).
