**What's new in 0.5.1 — "the launcher remembers a name, not a path"**

- **A security fix for the hook launcher.** 0.5.0 made every hook start Python once by remembering the interpreter in `~/.claude/smartuse/interpreter` as an absolute path, and the launcher ran that path. The file is ordinary user state, and neither guard protected it: a writable state file chose the program every hook ran. Now the file may hold only `python3`, `python` or `py -3`, and the launcher looks that name up on PATH exactly as its probe would. Anything else in it is ignored and probed again. Still one Python start per event.
- **The file is human-only.** file-guard and bash-guard deny the model's writes to it, including the spellings Windows maps to the same file, with the reason "…or which Python runs the hooks". Deleting it is allowed: it only costs one probe.
- **bash-guard decides long commands in time.** One rule's matching time grew with the square of the command's length, so a long command could outlast the hook's 10 s timeout, and a hook that times out lets the command through. It is linear now: 16 KB went from 12 s to about 1 s on the author's laptop.
- **Nothing to do by hand.** A 0.5.0 cache is replaced by a name on the first hook event. If your only Python is the Microsoft Store one or the Python install manager (3.14+, python.org's default), hooks keep 0.4.0 speed (two starts per event): their commands live under `WindowsApps`, and an alias there is never trusted.

**Tests:** `bash plugins/smartuse/hooks/tests/all.sh` → `run 138 · ledger 46 · until-done 40 · file-guard 20 · heartbeat 114 · ab 36 · watch 63 · wait 187`, green in CI on Linux, macOS and Windows, plus `claude plugin validate --strict`.

**Upgrade:** `claude plugin update smartuse@smartuse`. State stays under `~/.claude/smartuse/`. Windows users need Git Bash (Claude Code runs hook commands through it).
