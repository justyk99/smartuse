# Security

smartuse ships seven hooks: `bash-guard` (PreToolUse on Bash and PowerShell and, from Claude Code 2.1.314 (confirmed on 2.1.321), Monitor commands; with the fresh-source gate) and `file-guard` (PreToolUse), `ledger` (Stop / SubagentStop), `until-done` (Stop), `wait-gate` (Stop), `heartbeat` (every event; it records tool names, agent types and timestamps — never tool arguments, file contents or prompts) and `recall` (PreCompact / SessionStart). All are small Python files you can read in a few minutes. None makes network calls.

`recall` and the fresh-source gate read the session transcript (to find your prompts and the model's Reads), the human-only `.claude/smartuse.local.md` and, for `handoff:`, one file inside the repo. What recall prints passes a secret scrub (token prefixes, e-mail addresses, long digit runs) and a 9,000-character cap; its state holds counts and paths, never a command. A cloned repo or an archive can ship its own adapter, so every path value in it is checked as text before any file call: only plain local spellings are accepted (no share, device or automount path, no `:` after the drive letter, no part of only dots), a relative handoff or source never leaves the repo, and a link (a symlink, or a Windows junction or mount point) is refused rather than followed. After a send command matched, any failure to verify denies the call. So does a command the gate cannot read cleanly (a very long one, one with heredocs past the scan cap, several command substitutions, a `-c` / `eval` / `iex` / `cmd /c` / `-Command` string handed to another shell, PowerShell typographic quotes or escaped quotes, a PowerShell block comment `<#`, a PowerShell `Start-Process` (or `start` / `saps`) word anywhere, because its arguments are not read): while the job's sources are unopened it counts as a send, and the reason says why. A hook that misses Claude Code's own hook timeout lets the call through; the gate keeps its work inside a 4 s deadline for that reason, and the deadline starts when the hook starts, before the command is scanned. The PowerShell match is coarse: a publish word anywhere in a statement counts, and a form it cannot read (typographic quotes or dashes, an escaped quote, a block comment, a `Start-Process` word, a string handed to another shell) counts as a send while the sources are unopened. It is not claimed to read every PowerShell tokenisation; an adversarial tokenisation pass is parked for 0.6.2 and built when a real miss is reported. With `publish:` listed and a source unopened (right after a compaction, or before the sources are first opened), a PowerShell command that holds the word `Start-Process`, `saps` or `start` anywhere is denied once until the sources are re-read, including `npm start`, a `$start` variable or the word inside a quoted string. A backtick escape inside that word is not caught yet (parked for 0.6.2). The gate reads a command's text, so it cannot see a command built at run time. Some other ways of handing a command to another shell or interpreter are not yet recognised as such (other spellings of the same launchers, text fed on standard input, process substitution, shell functions and traps); they are parked for 0.6.2. In Bash, the join of a line that ends in a backslash does not check what comes before that backslash, so the line after an escaped backslash, or after a comment that ends in a backslash, can be misread (parked for 0.6.2). The frozen older rules are slow on a very long, dense command (when the sources are opened or there is no adapter, such a command can outlast the hook timeout); the contract lists each limit (`docs/notes/recall-design.md`, "Honest limits"). `ledger` reads your session and agent transcripts to sum token usage and writes to `~/.claude/smartuse/`; it never reads file contents other than the transcripts. `until-done` runs the repo's `check:` command only from the human-written adapter, only in fixed shapes or as a script pinned by hash in a root-owned file, with `shell=False`, and prints a redacted tail of its output.

**Guard levels and the switch (0.6.1).** The guards run at one of two levels, set in Claude Code's plugin options (`/plugin configure smartuse@smartuse`).
- **Light is the default.** It turns off two rules, `force-with-lease` (`git push --force-with-lease` runs) and `claude-json` (a read of `~/.claude.json` runs, as in 0.6.0), and the wait gate. Every other rule stays on, `secrets-dir` included. The owner may switch any other rule off by name (Rules off), except the three that protect the switch: `human-only`, `trust-pin`, `config-switch`.
- **Strict is every rule on.** The two light rules are denied, the wait gate runs, Rules off is ignored, and an unexpected error in `bash-guard` or `file-guard` denies the call. With no Python found, a guarded call is refused. An option value the hook cannot read counts as Strict.
- **Two waivers at every level.** A download piped into `python -m json.tool` is allowed. The word `sudo` is allowed when it only sits in text: a commit, tag or note message, `echo`, `printf`, `grep`, `rg`, or a `gh` title or body. A download into any other interpreter, and `sudo` as a command word, stay denied.
- **The switch is the owner's.** The hooks read the level from their own environment, which a command cannot change.
  - `file-guard` denies an edit of a Claude Code settings file that changes this plugin's options, its on/off entry, the switch that turns all hooks off, or a `CLAUDE_PLUGIN_OPTION_…` entry of `env`.
  - The always-on `config-switch` rule denies the plugin command's configure, enable, disable, uninstall and marketplace-remove verbs for this plugin, and an install that sets options.
  - It also denies a shell write, delete, move or overwrite of a settings file. Reading one stays allowed.
  - A rule that is off is shown at session start and on the status line; `/smartuse:doctor` prints the level.
- **The limit, by class.** The switch protection reads the text of a command.
  - A write hidden inside another program, or a command built at run time, is not seen.
  - Other spellings of the program's name, writers outside its list and escaped key names are not seen either.
  - A command that only quotes such a text, in a message for example, is denied.
  - A hard link to a settings file has its own path and is not matched.
  - A multi-line Edit of a settings file with CRLF line endings is denied, because its result cannot be computed.
- **Other limits of this release.**
  - The rules split out in 0.6.1 reuse their parents' patterns, which are slow on a long dense text (seconds at 30 KB). A hook that times out lets the call through. "Every rule linear" is on the ROADMAP.
  - The plugin's own installed files (`hooks.json`, the guards) are not guarded: editing them turns the guards off.
  - A switch from Strict to light is not shown at session start or on the status line.
  - Heartbeat events run in the background and can land out of order across a turn boundary, so a late event can reset a finished turn on the status line. `status.json` stays valid.

Report a vulnerability by opening a GitHub issue titled `security:` with no exploit details, or email the maintainer address on the GitHub profile. You will get an answer within 7 days.

Known limits: skills and output styles are instructions, not enforcement; the hook rules are regexes and can be bypassed by an actor who edits the hook file. Pair the kit with a deny list in `~/.claude/settings.json` and read-only database logins (see `docs/research/security-profiles.md`).
