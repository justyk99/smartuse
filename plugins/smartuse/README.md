# smartuse (plugin root)

The plugin that `justyk99/smartuse` publishes. Full README, benchmark and research live one level up: https://github.com/justyk99/smartuse

Install:
```text
/plugin install smartuse --marketplace justyk99/smartuse
```

Skills: `make-prompt` · `run-plan` · `living-docs` · `reply-style` · `ledger` · `receipts` · `status` · `doctor`. Hooks: `bash-guard` + `file-guard` (PreToolUse; bash-guard covers the Bash, PowerShell and Monitor tools and also holds the fresh-source gate, which denies a send command or an upload tool until the job's `sources:` are reopened after the last compaction, and the paid check, which denies a script that calls a per-call billed API until the owner's go in the adapter; file-guard keeps the adapter, the paid-run counter and the session transcripts read-only for the model) · `recall` (PreCompact / SessionStart — the summary is not a source; the `handoff:` note at session start) · `ledger` (Stop / SubagentStop — one receipt per plan step) · `until-done` (Stop gate) · `wait-gate` (Stop — a hand-off with nothing armed to wake the session is blocked once; off unless Strict or the Wait gate option is on) · `heartbeat` (every event — working / waiting on agent / waiting on you / stopped / stalled; its tool-event handlers run in the background). `hooks/watch.py`: the watcher a session runs in the background after a hand-off. Output styles: lcd · bluf · engineer · teacher · minimal · plain · memo. Evals: `evals/` (10 cases; the first 8 all passed with the plugin in the 0.4.0 run, mean gain +0.88 over no plugin: `evals/results/2026-10-22-0.4.0/`; all 10 pass on 0.5.0 with each case's own limits: `evals/results/2026-10-25-0.5.0-ci/`; run them with `--scaffold`, two cases stage a repo or a task folder). Tests: `hooks/tests/` — `bash hooks/tests/all.sh` runs every suite (plus the bench A/B dry run) and prints one summary line.

Switches (0.7.0): `/plugin configure smartuse@smartuse` sets three options, Strict guards, Rules off and Wait gate. Light is the default. It frees only `force-with-lease` and `claude-json` and turns the wait gate off. Strict is every rule on, the wait gate on, and guards that fail closed (Rules off is ignored).
- Each deny ends `[rule <name>]`. Put that name into Rules off to switch the rule off. `human-only`, `trust-pin`, `config-switch`, `settings-file` and `owner-file` cannot be switched off. New in 0.7.0: the rules `settings-file`, `owner-file`, `ps-download-exec`, `ps-rm-root`, and the paid check, named `paid` (always on in Strict; in light only in a repo whose adapter has a paid line).
- The paid check's adapter keys: `paid:` (the go: `render.py x 3, cap RM1, count --n, test ok`), `paid_scripts:` (file names, paths and patterns; `tools/batch.py only --pictures`), `paid_hosts:`, `paid_free:` (`--dry-run`, `tests/check_*.py`), `paid_guard: on`. The same go can be typed in the chat (`paid go: render.py x 3, cap RM1`, `test ok`, `paid stop`); only the owner's own typing counts. State: `paid-runs.json` under `~/.claude/smartuse/projects/<key>/`. It stops honest mistakes, not a forged approval; runs are counted, money is not. Details: the README and `SECURITY.md`.
- Claude cannot change the switches for itself: `file-guard` and the `config-switch` rule deny the edits and commands that would. The limit: they read text, so a write hidden in another program or built at run time is not seen, and a command that only quotes one is denied.
- `/smartuse:doctor` proves the hooks are live and prints the level. With no Python found, the session start says so once.
